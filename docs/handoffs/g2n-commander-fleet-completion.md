## Authority and source decisions

Frontier is the highest-priority **external account provider**. An identity-bound, connected, read-consented Frontier grant blocks redundant Inara account/goals reads before transport; broad Inara work is deferred. Current witnessed journal identities, loadouts/engineering and personal CG participation remain game evidence, not inferior calculated duplicates. Fetch time is not treated as an observation time and an expired CAPI current-ship reference cannot overwrite a witnessed sale/transfer. No new consent, queue, delayed/after-sale upload, provider write or authentication flow is introduced.

Community Goals reuses the verified G2M-A read-only CAPI `/communitygoals` contract (`activeCommunityGoals`), its rate limits, account identity checks, credential vault and normalized SQLite facts. The prior live audit is documented in [G2M-A Frontier audit](g2m-a-frontier-live-audit.md); this batch uses fixed synthetic transports, not a new live-account authorization. Unknown provider fields remain unsupported.

The [BGS-Tally reference](https://github.com/aussig/BGS-Tally/tree/3a15d9738fee2cddcc2bb0ddc0823cf10615ae66), its `bgstally/activity.py` and [tracking documentation](https://github.com/aussig/BGS-Tally/wiki/Usage-%E2%80%90-BGS-and-TW-Tracking) were inspected. Its core concept is per-system/faction/tick activity accounting and optional reporting, not a standalone page name. ERIDION retains an original native, source-backed subset. The upstream's inferred CZ success/election/war INF heuristics, manual adjustments, overlays, commander lookups, Discord/webhook/API reporting and complete Thargoid-war feature set are **not claimed**. Existing MIT credits/notices are in [G2K sources](../licenses/g2k/README.md); no new upstream code/assets are copied.

No license-cleared new ship imagery or documented avatar endpoint was established, so the existing ship icon/local commander portrait are used. No new FDevIDs dataset was imported; identity improvements use already bundled, attributed CSV fields only. Existing data/provenance and stock-versus-engineered distinctions remain.

## Verification and performance

Focused regressions cover Frontier/Inara request suppression; exact CG joins and stale precedence without fabricated participation; owner-only refresh; native launcher selection/reset/failure/viewer guard; matching versus foreign ship renames; complete bounded CAPI fleet paging/sold filtering/account isolation; exact activity totals and no ordinal addition; retained earned-merit repair. Existing G2M-C recovery, SQLite lifecycle, consent, revocation, keyboard, Spansh persistence and security regressions remain mandatory.

The final Windows/Linux CI runs Go/JavaScript/security/asset checks, Linux race detection, native smoke suites and the complete existing browser/lifecycle benchmark gates. New G2N Chromium evidence exercises explicit CG refresh with a fixed local Frontier transport, cards/compact layouts, Fleet/builds/stored modules, Statistics, contextual activity, launcher selection and cross-account isolation. It blocks external browser requests. Exact results and preview manifest/archive verification are added to the PR ledger after completion.

Performance design: no new journal reader, database writer, startup scan, schema or background provider loop. Existing normalized/history indexes are reused. Activity summaries cap at 100 rows, fleet pages at the requested 1–100 rows, and CAPI source at 512 ships. Portraits remain existing size-bounded local images. Only expanded builds load their history; account cards refresh on coalesced journal lifecycle changes. Existing CI lifecycle/resource artifacts provide measurements; no unmeasured improvement or total-app memory claim is made.
