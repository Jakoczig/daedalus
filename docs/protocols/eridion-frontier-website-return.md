# ERIDION Frontier HTTPS return — separate Proxmox deployment contract

This repository contains deployment source only in `scripts/frontier-return/`. Nothing is deployed by the desktop or this PR.

Register exactly `https://eridion.fitoserver.org/auth/frontier/callback`, public client ID `3a7cd51a-f629-4fec-b0c7-967bb7e2fa53`, scopes `auth capi`. The owner may override the public UUID in private local settings; there is no client secret. An inactive portal shared key does not establish live authorization.

1. Desktop generates independent 256-bit random state and PKCE verifier, S256 (binary SHA-256 then unpadded base64url), five-minute expiry, one active attempt. State is `erid1.<decimal-loopback-port>.<43-character-random-base64url>`; the full string remains bound to the desktop attempt, selected provider generation and receiver. No verifier/token leaves the desktop.
2. Authorize at the existing fixed Frontier OAuth endpoint with the exact HTTPS redirect above. The gaming-PC service already listens only on 127.0.0.1; no additional listener is opened.
3. Serve `index.html` at `/auth/frontier/callback` and `return.mjs` at `/auth/frontier/return.mjs` on that HTTPS origin. The website validates state shape and port 1024–65535, then builds ONLY `http://127.0.0.1:<port>/owner/frontier-callback?state=...&code=...` (or error). It ignores arbitrary redirect/host parameters. It clears the response from browser history, uses no-referrer, and offers a user-click return link plus explicit clipboard fallback. No fetch to localhost, cookies, analytics, storage, token exchange, credentials or arbitrary redirect is used.
4. Desktop checks the complete state, exact local receiver, expiry, generation and one-use status, consumes the flow, and exchanges the code using the ORIGINAL HTTPS redirect, never the loopback receiver. Token pairs rotate atomically through the OS vault; website receives none. Cancellation consumes a matching state; replaced/expired attempts are rejected.
5. Browser mixed-content/loopback policy fallback: owner copies the fixed local return from the HTTPS page and pastes it into Frontier → Manual browser return on the local desktop. This invokes the same state/receiver checks. Do not forward it to another person/device.

Deployment requirements: valid public HTTPS certificate, HTTPS only, Cache-Control: no-store, Referrer-Policy: no-referrer, X-Content-Type-Options: nosniff, CSP default-src 'none'; script-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'. Disable callback query logging at the reverse proxy and upstream, including error/access logs. Serve the module as JavaScript. No server-side session or token endpoint is needed. Test with fabricated callback values first. Confirm the website never logs or transmits codes to third parties. Authorization must run in the gaming PC's system browser, not the secondary laptop.
