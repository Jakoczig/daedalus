# Phase 1A execution plan

Implements Tasks 1–2 of the approved maintenance plan on
`origin/docs/maintenance-first-design-2026-11-11` at `620b246`, narrowed by
the maintainer's Phase 1A brief. Inara mapping/outbox implementation is deferred.

1. Add failing Node tests for session bootstrap, origin/Host validation,
   single-use pairing, expiry/revocation, explicit RPC roles, redaction,
   preference preservation and credential writes.
2. Implement a shared preferences store and an authenticated socket boundary.
   Keep HTTP on loopback for the existing Go WebViews. Offer optional direct TLS
   on a separate port for remote read-only displays. Never trust proxy headers.
3. Authenticate the client before socket connection; add pairing UI, owner
   pairing/revocation controls and write-only integration credentials.
4. Add real local HTTP/WebSocket regression tests and OAuth callback state tests.
   Require tests and focused lint in CI on Linux and Windows; retain client and
   Windows Go build jobs. No dependency upgrades or live provider requests.
5. Verify official Inara contracts and EDMC behavior; document Phase 1B scope,
   Windows smoke procedure, checks and remaining limitations. Review the whole
   diff, commit coherent changes and open a draft PR to the fork's main.

Security decisions: loopback processes and same-origin localhost pages are the
local owner trust boundary; remote sessions require TLS and explicit pairing.
Sessions are memory-only, expire after 12 hours and die on restart. Pairing codes
expire in five minutes. Remote RPC is an explicit read-only allowlist; unknown
methods fail closed. Secret storage remains the existing per-user preferences
file for compatibility; OS vault migration is separate CAPI work.

Verification: `npm run test:unit`, `npm run lint:security`,
`npm run build:client`; Windows Go compilation and WebView smoke via existing CI.
Fresh read-only security investigation and final bypass/regression review are
required by the fix-finding workflow.
